# Aether Pending Acceptance Checklist

## 最新修改（2026-03-11）

- [ ] 【显示修复】快捷键面板搜索框不再出现“四个灰色角”的系统焦点角标（使用无焦点环控件 + 自定义背景）
- [ ] 【耳机单击】耳机单击回退路径已恢复，Aether 再次能接到单击动作
    建议重点验收：
    1) 单击能触发 Aether 映射动作；
    2) 不会长期停留在“麦克风关闭”状态；
    3) 连续单击时不会误触发双次
- [ ] 【耳机滴滴 / 麦克风静音副作用】当前仍需专项验收，不能视为已完美解决
    当前结论：只要继续依赖 `AVAudioApplication.inputMuteStateChangeHandler` 充当耳机单击，这条链路就天然带有系统麦克风静音语义，可能伴随系统提示音、麦克风开关播报或识别链路抖动；本轮只做了“恢复功能 + 降低副作用”，还不是“理论上彻底无副作用”的最终解
- [ ] 【耳机单击事件源切换】新增 `CGEventTap` 捕获 `.systemDefined` 媒体键事件并吞噬（避免系统静音语义）
    建议重点验收：
    1) 已授权辅助功能时，AirPods 单击/双击/三击可稳定触发 Aether 动作；
    2) 系统媒体控制不再被触发（无“滴滴”/播报/静音副作用）；
    3) 未授权辅助功能时，行为回退到原有路径且不崩溃
- [ ] 【头势触发】点头开启头控、摇头停止头控的触发阈值已下调到当前的 `80%`，比上一版更容易触发
    建议重点验收：
    1) 静止状态下点头更容易开启头控；
    2) 头控运行中摇头更容易停止；
    3) 灵敏度回调后不会因为轻微自然晃动频繁误触
- [ ] 【头势提示音】点头 / 摇头成功识别后，会先播放一声确认音再执行开关头控
    本轮代码已调整：优先播放系统 `Glass`，回退 `Hero / Ping / Tink`

## Browser HUD Performance

- [ ] 浏览器全屏播放视频时，HUD 应自动隐藏（功能保留）
    本轮代码已调整：在“前台浏览器 + 聚焦窗口全屏”之外，新增“当前系统媒体来源 bundle 必须就是该浏览器”校验，避免普通全屏网页误隐藏
- [ ] 退出浏览器全屏视频后，HUD 应自动恢复显示
    本轮代码已调整：
    1) HUD 重定位仅在输入态或显式诊断时执行 AX 重查询；
    2) HUD 锚点追踪写文件默认关闭（`hudAnchorTraceEnabled=false`）；
- [ ] 【BUG】全屏播放视频时，HUD 没有跟随光标一块隐藏（应实现视觉同步）
- [ ] 【BUG】在 Edge 等浏览器中，处于普通网页全屏（非视频全屏）时，HUD 会错误地自动隐藏
- [ ] 【长期优化方向】针对多重同名指令（如 Edge 的两类全屏，或其它 APP 的同名菜单冲突）：
    1) **意图消歧**：HUD 提供多重选择机制，允许手动精准选择执行路径；
    2) **智能学习**：记录用户选择偏好，高频路径自动提权；
    3) **超时自动选择**：一定时间内未手动选择时，按默认/最高权重路径自动执行，确保语义不因冲突而中断
