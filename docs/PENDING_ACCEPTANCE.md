# Aether Pending Acceptance Checklist

## 当前重点验收（2026-03-17）

- [ ] 【AirPods 右耳修复】只戴右耳时，语音识别应能正常工作（已通过切换侧边重启引擎修复），头控不应出现超时。
  验证重点：右耳单独使用、左右耳热切换、切换后的语音首字响应

- [ ] 【耳机麦克风切换】连接/断开耳机后应自动跟随正确的输入设备；麦克风列表只显示真实可选设备
  验证重点：热插拔、播放设备切换、左右耳切换、识别中路由切换

- [ ] 【AirPods 语音稳定性】AirPods 作为输入时语音功能应稳定工作，不应出现 HUD 已切耳机但语音无响应
  验证重点：PTT 首句是否完整、菜单栏橘色麦克风是否稳定、AirPods 会话内不应自发重启/回落

- [ ] 【启动时耳机自动开启】启动时若耳机已连接且"自动开启"已打开，应立即生效（语音输入/控制/头控三类）
  验证重点：冷启动时耳机已连接，三类自动开启是否都立即执行


- [ ] 【回中按当前屏幕】在多显示器环境下执行“回中”时，应回到当前所在屏幕中心，而不是所有屏幕联合区域的中间
  验证重点：主屏/副屏分别回中、回中后指针是否留在当前屏幕、跨屏后再次回中是否切到新屏幕中心

- [ ] 【头势临时提示不被收成小点】点头/摇头触发的临时 HUD 提示不应立刻被 standby persistent HUD 压成一个点
  验证重点：连续点头/摇头时 HUD 是否完整展示文案、提示期间是否被小点覆盖、结束后是否正常回到 standby


- [ ] 【自定义快捷键多 App / 全局规则】一条自定义快捷键规则应支持绑定多个 App，也支持留空作为全局规则
  验证重点：单条规则绑定多个 App 后都能触发、空目标规则对所有 App 生效、老的单 App 规则升级后仍可正常使用

- [ ] 【自定义规则编辑可取消】新增自定义规则后应支持直接取消，不必先完成再删除；取消未保存的新规则时应自动撤回该空规则
  验证重点：新增当前 App 规则/全局规则后点取消是否直接关闭、未保存规则是否自动消失、编辑已有规则后点取消是否保留原值

- [ ] 【自定义规则可读性】多 App 规则卡片和快捷键面板的 App 名/快捷键展示应清晰易读，不应出现冗余摘要或不自然的蓝色快捷键文本
  验证重点：多 App 规则显示叠放图标和逐项名称、规则卡片不再出现“XXX 等 x 个 App”、快捷键面板改为统一键帽样式且 hover 态自然

## 暂缓项（当前版本先不验）

- [ ] 【语音按需夺回 (On-Demand Takeover)】当前版本已先回退到“单会话稳定优先”，不再把这条激进策略作为本轮验收门槛
  说明：后续若重新引入按需夺回，需要基于稳定版单独设计并另开验收

- [ ] 【耳机健康监测 (Headset Health)】当前版本已停用“会话内自动探测失败后切回普通麦”的策略，不再作为本轮必验项
  说明：后续若恢复这条能力，应放到会话边界外重做，并单独验“误判率”和“首句损失”

## 历史功能，待后续回归

- [ ] 【头势识别】点头/摇头稳定性、阈值和误触控制
- [ ] 【头势提示音】点头/摇头成功后的提示音体验
- [ ] 【耳机按钮动作】耳机单击/双击/三击不应触发 Aether 动作
- [ ] 【浏览器全屏视频 HUD】全屏播放时 HUD 应自动隐藏，退出后恢复
- [ ] 【浏览器普通全屏误隐藏】普通网页全屏不应误触发 HUD 隐藏
