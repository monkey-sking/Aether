# Aether Pending Acceptance Checklist

> 文档状态：`Current`
> 说明：这是当前待验收与已通过项的活清单。新的验收结论优先写这里。

## 当前重点验收（2026-03-27）

- [ ] 【全文优化入口体验】触发“全文优化 / 全文纠错优化”时，不应先明显全选整段文本再进入优化态；HUD 反馈也应更顺滑，避免用户感知为“先全选，再开始优化”
  验证重点：触发后是否直接进入优化反馈、处理前是否出现明显全选闪烁、优化完成后是否稳定替换原文并把光标放回合理位置

- [ ] 【处理阶段 HUD 辨识度】用户说完后的处理阶段，HUD 当前的“三道杠 / 两竖杠”提示不够明显，需要优化辨识度
  验证重点：处理态与听写态/待机态是否一眼可区分，不同背景和不同缩放下是否仍然清楚

- [ ] 【唤醒模式听写误回待机】在唤醒模式下进入听写后，听写过程中不应中途掉回待机 HUD，也不应因此提前停止听写
  验证重点：唤醒后连续听写、短暂停顿后续说、尾音处理阶段这几种情况下，HUD 是否持续保持听写/处理中语义，而不是无故回到 standby

## 暂缓项（当前版本先不验）

- [ ] 【语音按需夺回 (On-Demand Takeover)】当前版本已先回退到“单会话稳定优先”，不再把这条激进策略作为本轮验收门槛
  说明：后续若重新引入按需夺回，需要基于稳定版单独设计并另开验收

- [ ] 【耳机健康监测 (Headset Health)】当前版本已停用“会话内自动探测失败后切回普通麦”的策略，不再作为本轮必验项
  说明：后续若恢复这条能力，应放到会话边界外重做，并单独验“误判率”和“首句损失”

## 历史功能，待后续回归

## 已验收存档

- [x] 【头势临时提示不被收成小点】点头/摇头触发的临时 HUD 提示不应立刻被 standby persistent HUD 压成一个点
  验证重点：连续点头/摇头时 HUD 是否完整展示文案、提示期间是否被小点覆盖、结束后是否正常回到 standby

- [x] 【回中按当前屏幕】在多显示器环境下执行“回中”时，应回到当前所在屏幕中心，而不是所有屏幕联合区域的中间
  验证重点：主屏/副屏分别回中、回中后指针是否留在当前屏幕、跨屏后再次回中是否切到新屏幕中心

- [x] 【启动时耳机自动开启】启动时若耳机已连接且"自动开启"已打开，应立即生效（语音输入/控制/头控三类）
