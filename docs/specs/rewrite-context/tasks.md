# 实施计划：全文优化上下文模型

## 概述

本任务清单将 `rewrite-context` 的产品定义拆成后续可执行工作。当前文档阶段属于 `product/design`，不等于已经进入代码实现。

## 阶段划分

### 阶段 1：产品定义与信息架构

- [ ] 1.1 确认 Rewrite Context 的用户可见命名
  - 定义中文和英文用户文案
  - 区分“短期上下文”和“长期偏好”
  - _需求：7.1, 7.4_

- [ ] 1.2 确认 v1 支持的场景类型
  - 固定至少 4 类：即时沟通、正式表达、技术写作、结构化输入
  - 定义每类场景的优化目标和边界
  - _需求：2.1, 2.2_

- [ ] 1.3 定义上下文继承与隔离规则表
  - 输出“哪些场景允许继承、哪些必须隔离”的矩阵
  - _需求：4.1, 4.2, 4.3_

- [ ] 1.4 定义用户控制面板的信息结构
  - 是否启用上下文
  - 清空短期上下文
  - 清空长期偏好
  - _需求：7.1, 7.2, 7.3_

### 阶段 2：上下文识别策略

- [ ] 2.1 定义“同一写作任务”的判定规则
  - 内容连续性
  - 时间窗口
  - 场景稳定性
  - _需求：1.1, 1.2, 5.1, 5.2_

- [ ] 2.2 定义强信号和弱信号体系
  - 内容、时间、场景为强信号
  - App、窗口、目录为弱信号
  - _需求：6.1, 6.3, 6.5_

- [ ] 2.3 定义低置信度回退规则
  - 无上下文回退
  - 仅长期偏好回退
  - 完全保守回退
  - _需求：8.1, 8.2, 8.3_

### 阶段 3：数据与 prompt 设计

- [ ] 3.1 设计短期任务上下文的数据结构
  - 保存任务摘要而不是无限历史全文
  - _需求：1.2, 3.4_

- [ ] 3.2 设计长期偏好的数据结构
  - 以场景偏好为主，而不是以 App 为主
  - _需求：3.1, 3.3, 3.4_

- [ ] 3.3 设计上下文摘要到 prompt 的注入格式
  - 规则摘要
  - 术语约束
  - 场景说明
  - _需求：2.2, 3.2, 8.2_

- [ ] 3.4 约束历史注入上限
  - 限制 token 成本
  - 防止旧文本污染当前任务
  - _需求：4.4, 8.1_

### 阶段 4：实现拆分

- [ ] 4.1 在 Rewrite 请求链路中加入上下文决策层
  - 在调用 LLM 前完成任务/场景判断
  - _需求：1.4, 2.2, 6.1_

- [ ] 4.2 实现短期任务上下文存取
  - 写入任务摘要
  - 按条件过期
  - _需求：1.2, 1.3_

- [ ] 4.3 实现场景偏好存取
  - 只沉淀可解释的偏好项
  - _需求：3.1, 3.4_

- [ ] 4.4 接入设置页的上下文开关与清理入口
  - _需求：7.1, 7.2, 7.3_

### 阶段 5：验证与回归

- [ ] 5.1 设计场景化验证用例
  - 聊天连续修改
  - 邮件连续润色
  - 技术文档术语保持
  - 表单最小改动
  - _需求：2.1, 4.1, 5.2_

- [ ] 5.2 验证误继承风险
  - 跨场景污染
  - 错误项目术语泄漏
  - _需求：4.1, 4.4, 8.1_

- [ ] 5.3 添加 Insights 标记字段
  - 是否命中短期上下文
  - 是否命中长期偏好
  - 是否回退为无上下文
  - _需求：9.1, 9.2_

- [ ] 5.4 定义上线后观察指标
  - 重试率
  - 接受率
  - 用户关闭率
  - _需求：9.3, 9.4_
